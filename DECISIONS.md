# Decisions

1. **No PostGIS ORM types.** The DB image is PostGIS (per brief) but campus points are plain `lat`/`lon` floats with a haversine helper; keeps unit tests runnable on SQLite. Upgrade path: GeoAlchemy2 columns when footprint polygon queries need spatial indexes.
2. **bcrypt used directly instead of Passlib.** passlib 1.7.4 is unmaintained and breaks on Python 3.13 / bcrypt 4+. Same hashing algorithm.
3. **MFA:** TOTP enrolment via `/mfa/setup` + `/mfa/verify`. Once enabled, login requires `otp`. Enrolment itself is not forced for officers at login in the demo; `MFA_REQUIRED` is surfaced in the UI as a nudge (enforcement deferred to phase 8).
4. **Alembic:** hand-written migrations, one per phase that adds tables.
5. **Local dev:** Python 3.13 venv works for tests; Docker image pins 3.11 as per brief. Tests run on SQLite, runtime on Postgres.
6. **Empty routers** in phase 1 (documents, precheck, verification, rules, risk, alerts, audit) are filled in by their phases.
7. **Deterministic signed PDFs.** RSA test keys come from a seeded prime generator (`make_test_pki.py`; test-only, never use for real). Signing time, PDF `/ID`, Info `/ModDate` are pinned by monkeypatching pyHanko (`generate_synthetic.py`); PyMuPDF's random trailer ID after the tamper edit is rewritten deterministically.
8. **Planted tamper = real post-signing edit.** C's land document is signed, then the survey number is redacted and re-inserted in Times via an incremental update. pyHanko reports `intact`+`valid` but a non-LTA modification level; test asserts this.
9. **Static vs yearly documents.** Land, occupancy, structural, fire docs depend only on the institution, so they are byte-identical across years (A's land + occupancy are the carry-forward demo). Affidavit, TER, satellite map, audited accounts are per year.
10. **Extra expected flags.** `ISSUER_MISMATCH` on C's land doc (DigiLocker holds the original survey number) is listed as planted: it is the issuer corroboration for the CRITICAL tamper rule. `MISMATCH_CROSS_YEAR` (survey number) and B's occupancy "no API" `ISSUER_UNAVAILABLE` are listed under `optional`.
11. **Mock portal behaviour.** Karnataka fire portal always 503 (A); Maharashtra occupancy portal has no API (501, B). B's main block (1990) triggers the >30-year structural certificate requirement; B's provisional OC history sits in the mock AICTE record.
12. **Built-up area check is application-level:** sum(footprint x floors) vs sum(declared). C: 24,100 vs 31,500 m2.
13. **Faculty cadre:** valid faculty N is split professor=ceil(N/9), associate=ceil(2N/9), rest assistant, so cadre norms pass for A, B and C's valid 97; C's 12 duplicates are Assistant Professors.
14. **Extraction runs synchronously** at upload (fast on templates); the Celery task in phase 6 wraps `process_document`. Upload endpoint is a sync `def` because pyHanko's sync validators cannot run inside the event loop.
15. **QR decoding:** pyzbar first (Docker image has libzbar0), OpenCV `QRCodeDetector` fallback because pyzbar's DLL does not load on this Windows machine.
16. **Signature status** is stored on the document (`dsc_status`, `dsc_info` JSON incl. PDF metadata). `SIGNED_MODIFIED` = signature valid over its own revision but later revisions changed the document (pyHanko modification analysis).
17. **No OCR yet:** pages without a text layer produce a `MANUAL_REVIEW_REQUIRED` placeholder field; the `FEATURE_OCR` hook is marked in `pipeline.py`.
18. **Generator fix:** long values are shrunk to fit the page (an address was clipped at the page edge, caught by the extraction ground-truth test).
19. **Rule engine shape.** Engines in phase 5 are thin wrappers over `evaluate_pack` (completeness = document_required/field_required/expiry; consistency = consistency/timeline; compliance = formula/threshold). Every rule carries a `code`, the flag code emitted on FAIL.
20. **Category-driven document rules.** `categories.yaml` lists required documents (with `inherits`); the loader generates one `document_required` rule per (category, document type). A new category needs no rule code.
21. **`dsc_valid` means "has a digital signature"** (any status except UNSIGNED). Broken or tampered signatures are the Authenticity engine's job, so a tampered document does not also appear as DOC_UNSIGNED.
22. **Valid faculty** = full-time rows minus IDs the (mock) AICTE registry shows full-time at another institution. Stored as derived/system facts; the compliance context reads only facts.
23. **No separate programmes/buildings tables.** Programmes, buildings and infrastructure live as form-sourced facts; revisit if editing of the form is needed.
24. **Expiry rules come in pairs** per document: valid on the academic-year start (DOC_EXPIRES_BEFORE_AY) and valid at submission (DOC_EXPIRED).
25. **Adapter plumbing** (`adapters/base.py`) uses httpx with a 5 s timeout and 2 retries; tests inject a TestClient of the mock service. Network failure yields `http_status=None`, which phase 5 maps to SOURCE_UNAVAILABLE.
26. **Seeded packs:** v1 active; v2-demo imported as a draft for the versioning demo (dry-run diff arrives with scoring in phase 6).
27. **Adapters consolidated** in `adapters/sources.py` (SHCIL, DigiLocker, UDIN, fire NOC, occupancy, website, footprints) plus `aicte_records.py` and `accreditation_lists.py`, instead of one file per source. Same pluggable base URL.
28. **Issuer outcomes.** SOURCE_UNAVAILABLE (503, no-API 501, network failure) always adds a second MANUAL_REVIEW_REQUIRED row plus an INFO flag. Expiry is judged against the submission date, so B's fire certificate (valid to 2027-06-30) is VERIFIED at the issuer and only flagged by the Completeness rule. Structural certificates have no issuer source, so they are MANUAL_REVIEW_REQUIRED.
29. **Proof levels** are stored per document: ISSUER_VERIFIED = valid trusted unmodified signature (and QR match) plus a VERIFIED issuer check, CRYPTOGRAPHIC = signature only, FORENSIC_ONLY = otherwise. Forensic findings weigh MAJOR / MINOR / INFO respectively; any forensic finding corroborated by a signature failure, QR mismatch or issuer mismatch on the same document is CRITICAL.
30. **Forensics implemented:** font inconsistency inside field regions, PDF metadata anomalies, EXIF editor tags, and ELA heatmaps (stored as evidence; not used to raise flags on their own because crisp rendered text gives high ELA everywhere). Copy-move (ORB) and DocTamper stay behind FEATURE_DTD, not wired.
31. **Photo reuse** uses a blurred perceptual hash compared across centre-crop fractions (true copy = distance 2, unrelated >= 14, threshold 8). A plain phash gave 14 for the copy and 16 for unrelated photos, which was too close; ORB matching was tried and does not discriminate grainy synthetic images.
32. **Later uploader flagged, earlier owner gets INFO** (documents, photos, faculty). Hence A carries INFO flags about its photos being reused by C.
33. **Flag identity:** each flag has a fingerprint (engine|code|rule|document|key); re-running the pipeline upserts, so officer decisions on a flag survive and flags that no longer apply are removed.
34. **Engine routing by rule code:** completeness handles document/field/expiry rules and PROVISIONAL_OC_LIMIT_EXCEEDED; the NAAC eligibility rule is evaluated in the issuer engine; other formula/threshold rules are compliance; consistency/timeline rules are consistency.
35. **Scoring:** weights from the active pack's risk.yaml (CRITICAL 40, MAJOR 15, MINOR 5, INFO 0); forensic flags count weight x confidence; dismissed flags are excluded but kept. RED = any CRITICAL or score >= 60; AMBER = any MAJOR or score >= 20. An application is scored with the pack version it was last validated under, so activating a new pack never changes old results.
36. **B stays a DRAFT in the demo seed** (unlocked, already scored AMBER) so the pre-check step works; it joins the officer queue when it submits. The queue and inspection list default to the latest academic year that has submitted applications.
37. **Pre-check** runs the same pipeline inline by default (`USE_CELERY=true` sends it to the worker). The fix-list hides forensic/authenticity indicators from institutions (officer-only) and summarises INFO items as 'waiting for officer confirmation'.
38. **Audit** entries are written by every state-changing path (login, uploads, extraction, engine runs, verification calls, scoring, decisions, submit/reopen, rule-pack create/validate/dry-run/activate, report generation). Failed logins are logged too. Single-writer assumption is marked in code.
39. **Reports:** the footer hash is the SHA-256 of the report rendered with a placeholder footer (a document cannot contain its own hash); the audit log stores the SHA-256 of the final file.
40. **A has 26 faculty** so the v2-demo (1:18) dry-run produces a visible GREEN -> AMBER change for A; C's shortfall message changes from 23 to 37. B is unaffected.
41. **Retention** is a config table plus a listing function; nothing is deleted automatically.
42. **Map has no base tiles by default.** Satellite/street tiles would be an external call; the Leaflet map shows campus point, radius, building footprints and photo markers over a plain grid. Set `VITE_TILES_URL` to enable tiles.
43. **MODIFIED_AFTER_SIGNING shows what changed:** the first signed revision is re-read and compared field by field with the current file, so the flag cites the exact field and bounding box (survey_no was SY-118/4B, now SY-118/9C).
44. **Adapters share one pooled HTTP client** (per-call clients made 100+ faculty-registry lookups take ~1 s each on Windows because `localhost` tries IPv6 first). Use `127.0.0.1` for `MOCK_ISSUERS_URL` when running outside Docker.
45. **Frontend typing is loose** (`J = any` for API payloads) to keep the code small; generate types from `/openapi.json` if the API grows.
46. **Page layout targets 1366x768 and wider**; below ~1100 px columns stack, but the PDF viewer keeps a fixed 520 px width.
47. **Evaluation harness** (`scripts/_harness.py`) builds a fresh SQLite world with generated data and in-process mock issuers; `verify_planted.py` and `evaluate.py` share it. Measured: 41/41 documents classified, field P/R/F1 1.000 on the synthetic templates, 15/15 planted flags, verification rate 28/32 (the 4 misses are the planted unavailable sources).
48. **Optional features:** OCR, YOLO PC counting and LLM drafting are wired behind flags with lazy imports; LayoutLMv3, face matching, DocTamper, RAG and real geo data are only flags. OCR is tested with a stand-in engine because PaddleOCR is not installed here.
49. **Migrations are tested against the models** (`tests/test_migrations.py`) because all other tests use `create_all`; this caught a SQLite-incompatible unique column and led to a unique index. The Postgres path itself is still unrun.
50. **Compose:** backend/worker share a `storage` volume and get `TRUST_ROOT_PATH`/`STORAGE_DIR` so the API can validate signatures against the generated test CA.

## Corrections after checking the official APH 2024-27 PDF (printed page = PDF page - 16)

51. **Citation fixes in both rule packs:** PG Engineering ratio is Annexure-5, 5.3 on p.96 (was p.95); UG Computer Applications/Management 1:25 is 5.2 on p.95 (was p.96); computer centre norm is on p.88 (was p.87); DSC-signed upload is Clause 2.3.4 (a) (was 2.3.5, which is the random-EVC/fraud clause); data-accuracy duty is Clause 2.3.3 (a) on p.14; survey-number consistency now cites Affidavit-2 item 15 (p.186) instead of Annexure-14 (which only lists state competent authorities); fire-certificate validity cites Annexure-2, 2.1 (v) on p.81; clause texts now name the exact sub-clause.
52. **Cadre ratio 1:2:6 applies to UG Engineering only:** Annexure-5, 5.3 (p.96) uses R = 1+1+1 for PG Engineering and HMCT; 1:2:6 is for UG and for MCA/MBA. FAC-CADRE-ENGG now applies to level UG.
53. **Land document is not an EoA requirement:** Annexure-2, 2.1 (p.81) lists seven EoA documents and no land record (land documents belong to new institutions, Annexure-1, and change of site). It was removed from the EoA checklist; an uploaded land document is still classified, verified and checked for tampering. Faculty list and infrastructure photos stay as prototype requirements, now cited to Clause 6.14 (c) / Affidavit-2 item 9 (p.55) and Clause 1.9 (f)-(g) EVC video with GPS at the main entrance (p.8).
54. **TER charges follow Table 2.1 (p.13):** EoA on self-disclosure is Rs 0.20 lakh per division of applied intake for non-government institutions, +10% a year from 2024-25 (p.14 note i). Receipts and mock AICTE records are generated from `rulepacks/config/ter_fees.yaml` (A 2027-28: 2 divisions -> Rs 53,240).
55. **Affidavit 2 deponent is the Chairperson/Secretary of the Trust** (Annexure-2, 2.1 (i), p.81; Affidavit-2 format, p.186), not the Principal; synthetic data updated.
56. **Previous-year photos carry previous-year EXIF dates.** Copying 2027 photos into the 2026-27 applications made them look taken after that year's submission (three spurious MINOR METADATA_ANOMALY flags on last year's applications).
57. **Deadline rule cites the page of Clause 2.2 (b):** the "last date" for submission and TER payment is Clause 2.2 (b) on p.12, not p.15; TL-DSC-BEFORE-DEADLINE now cites p.12 and names Clause 2.3.4 (a) (DSC upload, p.15) in its clause text.
58. **Synthetic photos are dated 11-13 September 2026 (were January 2027).** The photo-time check flags a capture time after the submission date or more than 3 years before it. The synthetic submissions are 1 March 2027 (and 2026 for last year), but a live demo submit uses the real date, so January 2027 photos produced three spurious MINOR `METADATA_ANOMALY` notices on B (score 37.5 instead of 30). September 2026 passes for the synthetic submissions and for a live submit on any real date from 13 September 2026 to the end of 2029; after that the generator's photo dates need moving forward. `tests/test_workflow.py` now asserts that submitting B on the real date raises no `METADATA_ANOMALY`.

## Merge of the old implementation, the restart scaffold and the TatvaAI build (2026-10-26)

59. **One tree: the full implementation from `_old` is the base.** The restart scaffold (`tatvaai` main branch) had a stub API and sample-size rule pack/generator; the old code has the real engines, rule packs, tests, CI and Docker. This supersedes the earlier "rebuilt from scratch, copy from the archive on purpose" decision, which stays in the git history of `main`. From the restart scaffold we kept `BUILD_GUIDE`, `FEATURE_LIST`, `CLAUDE.md`, `contracts/openapi.json` (now regenerated from the real app) and `backend/scripts/export_openapi.py`.
60. **Old generator, rule pack, mock issuers and PKI script win over the scaffold's rewrites.** The scaffold's rule pack is a 30-line sample in a different schema, and its generator emits a different data layout; the engines and 62 tests are built on the old formats. The rewrites remain on `main` for reference.
61. **No admin role.** Three roles only. Rule packs (create, validate, dry-run, activate, draft-from-text), audit verify/export and reopen-once moved to the officer. The user-management endpoints and page were deleted: with no admin nobody should be able to create accounts or promote roles from inside the app. Their pages moved from `frontend/src/pages/admin/` to `pages/officer/`.
62. **Inspector on-site verdicts (from the TatvaAI prototype).** The inspector marks each flagged item CONFIRMED or CLEARED with a mandatory note; the officer's ACCEPT/DISMISS screening is separate and unchanged. Stored as columns on `flags` (migration `0006`, so the contract stays at 19 tables); the checklist is grouped by source document with a progress count. Only inspectors can record a verdict; officers see it read-only.
63. **Everything else in the TatvaAI prototype was already here, in more complete form** (alerts, audit chain, PDF report, signature validation, categories, norms, carry-forward), so it was not copied; the prototype stays in its own repo.
